Factory Inventory Management System

System architecture, tech stack and data flow. "Catalyst Components" demo app for the Claude Code workshop.

System architecture

Two processes on localhost. The browser talks to FastAPI directly over HTTP; there's no proxy, database or auth server.

Tech stack

Minimal on purpose: three runtime dependencies on each side.

Frontend

Vue 3 + Vite

  • vue ^3.4, Composition API (setup())
  • vue-router ^4.3, HTML5 history
  • axios ^1.6 for HTTP
  • vite ^8, dev server on :3000
  • Charts: hand-written SVG; layout: CSS Grid
  • i18n: custom composable, English and Japanese
Backend

Python FastAPI

  • fastapi ≥0.110
  • uvicorn ≥0.24 ASGI server, :8001
  • pydantic ≥2.5 response models
  • Managed with uv (pyproject.toml)
  • Auto docs at /docs

Files, tests, Claude Code

  • pytest + FastAPI TestClient in tests/backend/

Data flow — a filter change on the Dashboard

The same pattern drives every filtered view.

  1. User picks a filterTime Period, Location, Category or Order Status in FilterBar.vue writes to a module-level ref in useFilters.js. Every view shares that ref.
  2. View reactsA watcher in the view calls api.getDashboardSummary(filters), getOrders, getInventory and so on. Values of 'all' are left out of the query string.
  3. HTTP requestaxios sends GET http://localhost:8001/api/dashboard/summary?warehouse=Tokyo&month=Q1-2025. CORS allows any origin.
  4. Server filters in memoryapply_filters() matches warehouse exactly, and category and status case-insensitively. filter_by_month() substring-matches order_date, expanding quarters through QUARTER_MAP. Inventory has no date, so the month filter is skipped for it.
  5. Aggregate and validateSummary values (inventory value, low-stock count, pending orders) are computed per request. List endpoints are validated against Pydantic response_models.
  6. RenderThe JSON lands in refs. computed properties derive the KPIs and chart series, and Vue re-renders only what changed.

Findings

Gaps a reader should know about. Several look like planned workshop exercises.

Tasks API not implemented. client/src/api.js:77-95 calls four task endpoints that server/main.py doesn't define. The browser console logs "Failed to load tasks" on every page load.
Purchase-order API not implemented. PurchaseOrder and CreatePurchaseOrderRequest models exist (main.py:104-122) and purchase_orders.json is empty, but no route uses them.
Backlog view isn't routed. views/Backlog.vue exists, but main.js has no /backlog route and App.vue has no nav link.
Reports bypasses the API client. Reports.vue:156,162 hard-code http://localhost:8001 instead of going through api.js.
Demo-only security. Auth is a hard-coded mock user (useAuth.js), CORS is *, there's no rate limiting, and nothing persists between restarts.
